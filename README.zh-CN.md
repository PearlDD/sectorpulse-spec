# SectorPulse

[English](README.md) · [验证记录](VERIFICATION.md) · [初始仓库检查](BASELINE.md)

SectorPulse 是一个可在浏览器中运行的板块轮动研究工具，对比 11 个 SPDR 行业 ETF 与 SPY，展示相对表现、宏观数据和可解释的确定性评分。

**仅用于教育与研究，不构成投资建议，也不保证预测准确性。当前版本不调用任何大模型。**

## 当前可以做什么

- 点击 **Refresh analysis** 更新分析，查看最近更新时间和实际价格日期。
- 指定历史截止日期，查看板块排名、评分及 20/60 个交易时段相对 SPY 的表现。
- 点击板块，查看评分组成、周期加分理由和价格对比图。
- 在归一化到 100 的走势图与调整后价格图之间切换。
- 查看 FRED 宏观指标、单位、观察日期和数据缺失状态。
- 处理加载中、空结果、部分数据缺失和 API 错误；支持桌面和移动端。
- 使用明确标注的 **Synthetic demo** 演示模式；不会自动把模拟数据当作真实行情。
- 在浏览器本地保存数据源偏好，不需要登录。

## 本地启动

环境要求：Python 3.12、Node.js 24 LTS、npm；macOS 或 Linux。首次安装和实时数据请求需要联网。

切换到包含本 MVP 的 Git 分支，在项目目录运行：

```bash
cd sectorpulse-spec
bash run.sh
```

脚本会创建虚拟环境、安装锁定依赖、构建前端，并由 FastAPI 同时提供网页和 API。打开：

**http://127.0.0.1:8000**

按 `Ctrl+C` 停止。安装完成后，日常启动可以使用：

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

无需 API key 即可尝试实时价格分析。要离线演示，请选择 **Synthetic demo**，再点击 **Refresh analysis**。模拟价格和宏观输入仅用于展示功能。

### 可选：配置 FRED

```bash
cp .env.example .env
```

在项目根目录的 `.env` 中设置 `FRED_API_KEY`，然后重启后端。也可以通过服务器环境变量提供。密钥只在服务器使用，不写入前端，不提交到 Git。缺少密钥时，宏观指标显示不可用，价格分析仍可运行，周期加分关闭。

## 评分与数据边界

```text
评分 = 0.4 × 20 时段相对收益 + 0.6 × 60 时段相对收益 + 周期加分
```

相对收益是板块收益率减去 SPY 收益率，单位为百分点。属于现有周期映射的板块加 2 分，其余加 0 分。相同分数按 ticker 字母顺序排序。评分是描述性指标，不是上涨概率或买卖信号。

周期规则使用失业率最近三个观察间隔的变化和 10 年减 2 年美债利差：失业率升幅至少 0.3 个百分点为收缩；否则利差倒挂为放缓；否则失业率降幅至少 0.2 个百分点为复苏；其余为扩张。输入缺失或过旧时，周期为未知。

- `as_of_date` 包含截止日，默认使用纽约时间的昨天；拒绝当天未完成的交易日和未来日期。
- 所有参与排名的板块必须具备 SPY 最近 61 个观察交易时段的有效价格；缺失价格不会被填充，板块会被排除并说明原因。
- FRED 同时限制观察日期和历史数据版本；Yahoo 调整后历史价格仍可能被后续修订，因此不能宣称完全消除了回测前视偏差。
- MANEMP 是制造业就业人数，不是 PMI；CPI 展示的是指数水平，不是通胀率。

## API 与开发

| 路径 | 用途 |
| --- | --- |
| `/api/health` | 服务存活状态及配置状态，不包含密钥 |
| `/api/prices` | 各 ticker 的价格历史和不可用原因 |
| `/api/macro` | 宏观指标快照和缺失状态 |
| `/api/analysis` | 排名、评分明细、周期、图表数据和限制说明 |
| `/docs` | FastAPI 交互式 API 文档 |

分析示例：`/api/analysis?as_of_date=2025-01-31&mode=demo`。日期错误返回 422；价格完全不可用或基准不足返回 503；部分板块失败时仍返回可用结果。

运行全部检查：

```bash
.venv/bin/python eval/score.py
```

包含 pytest、Ruff、mypy、前端 TypeScript 检查、lint 和生产构建。历史验证详情见 [VERIFICATION.md](VERIFICATION.md)。

开发时分别打开两个终端：

```bash
.venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

```bash
cd frontend
npm run dev
```

访问 http://127.0.0.1:5173；Vite 会把 `/api` 转发给后端。

## 部署

提供 Dockerfile 和 Compose 配置，尚未部署到外部服务：

```bash
docker compose up --build
```

默认只绑定本机 `127.0.0.1:8000`。部署到容器平台时，使用容器端口 8000、健康检查 `/api/health`，通过平台的密钥管理提供 FRED key，并在入口启用 HTTPS。完整的同源部署及前后端分离说明见 [英文 README](README.md#deployment-configuration-not-deployed)。

Docker 配置语法已验证；先前环境没有运行 Docker daemon，因此没有宣称容器构建和启动已验证。

## 尚未实现与已知限制

AI 分析、RRG 图、资产配置建议、数据库、历史分析保存、账号系统、定时刷新、共享缓存和任务队列尚未实现。当前只保存浏览器数据源偏好。

实时提供商可能限流或缺少数据，严格的共同窗口要求可能导致可排名板块较少；失败重试时请求可能耗时数分钟。对公网开放前，需要补充限流、缓存和并发控制。实时 FRED 成功路径需要有效密钥；无密钥时的行为和历史版本请求参数已有测试覆盖。
